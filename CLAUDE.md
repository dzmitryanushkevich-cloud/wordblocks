# WordBlocks

Прототип словесной головоломки на русском. Игрок свайпом по соседним плиткам фигуры
собирает слово; как только слово найдено, оно засчитывается мгновенно, а вся фигура
рассыпается вместе с остальными спрятанными в ней словами. Пять фигур на уровень,
прогресс считается в буквах — поэтому короткое слово это потерянные буквы.

Считаются только слова из категорий уровня — они написаны над блоком (`Figure.scoring`).
Остальные слова языка в блоке неизбежны (ЛАЙ внутри ЛАЙМА, ЛИС внутри ЛИСЫ: чистых блоков
выходило 10 из 150) и потому безвредны: блок от них не рассыпается. Это правило держит
всю честность игры, не трогай его не подумав. Но и пропадать такому слову незачем —
оно уходит в копилку (см. ниже).

Главный конфликт игры: генератор специально кладёт в каждый блок длинное якорное слово
и короткое слово-соблазн — оба из темы. Без соблазна выбирать не из чего, а без длинного
якоря нечего искать.

## Команды

    npm install                  только для разработки
    npm run build                пересобирает wordblocks.html и docs/index.html
    npm run build -- --artifact  плюс dist/artifact.html для публикации в Claude
    npm run gen                  консольный прогон генератора: уровни 1, 5 и 10
    npm run gen -- en stats 40   то же для другого языка: первым аргументом код языка
    python tools/build-dictionary-en.py   пересборка английского словаря (нужен WordNet)
    npm run gen -- stats 200     статистика генератора по 200 уровням
    npm run gen -- themes 30     какие якоря попали в тему уровня
    npm test                     тесты ядра (vitest)
    npm run smoke                дымовой тест интерфейса в браузере (нужен playwright-core)
    npm run typecheck            проверка типов

## Устройство

Игра многоязычная по строению: всё, что зависит от языка, лежит в `src/content`
и передаётся в ядро параметром — словарь, категории с планом по уровням, кривая
сложности и тексты интерфейса. Ядро (рост фигур, пути, солвер, генератор, правила
партии) не знает ни одного языка. Сейчас в сборке два пакета: `ru` и `en`.
Новый язык — это новая папка в `src/content` и строчка в реестре
`src/content/index.ts`; ядро при этом не трогается вовсе. Если тянет положить
русскую строку в `src/core` или `src/ui` — это ошибка, строка идёт в пакет.

Язык выбирается при запуске: `?lang=ru` в адресе, потом выбор игрока из переключателя
на карте уровней, потом язык браузера, потом язык по умолчанию (русский). Прогресс
хранится отдельно на каждый язык. Дымовой тест читает русские подписи и поэтому
открывает игру с `?lang=ru` — иначе в браузере с английской локалью он падает.

Кривая у каждого языка своя, и это не формальность: английские слова короче
и коротких слов в языке в разы больше. Поэтому у `en` якорь доходит до десяти букв
вместо одиннадцати, а ограничения на число слов в блоке вдвое свободнее — иначе
валидатор бесконечно чинит блок из-за случайных CAT, EAR и PEA. Считаются всё равно
только слова темы, так что шум безвреден.

`src/core` — чистый TypeScript без React: словарь с префиксным деревом, рост полиомино,
солвер всех слов фигуры, генератор с валидатором, кривая сложности. Ядро гоняется из консоли
и из тестов, в нём не должно появляться ничего браузерного.

Словарь собран из открытого списка существительных и частотного списка субтитров
(`tools/build-dictionary.py`), 9829 слов. Один подвох там стоил игре целого класса
слов: pymorphy делит вероятность разбора между именительным и винительным падежом,
которые у неодушевлённых мужского и среднего рода совпадают, и прежний порог
«вес разбора ≥ 0,4» выбрасывал ЛЕС (0,38), ХЛЕБ (0,35), МОРЕ (0,22), ПОЛЕ, РОТ, СЫР.
Игрок находил ЛЕС и получал красный отказ «такого слова нет». Порог убран, вернулось
1800 слов. Если будешь трогать сборку словаря — проверяй не размер списка, а горсть
бытовых слов: лес, хлеб, море, поле, рот, сыр, рис, мёд.

Словарь вырос — и блоки стали плотнее: генератор знает больше коротких слов, поэтому
их в блоке больше (2,6 против 1,9). Потолок коротких слов в кривой поднят на единицу,
иначе валидатор чинил блок по 4,5 попытки вместо 2,9. Это безопасно: короткие слова
почти всегда не из темы, блок они не рассыпают, а теперь ещё и идут в копилку.

У каждого уровня есть тема: `src/core/themes.ts` раскладывает категории из
`src/content/<язык>/themes.json` (в каждом языке 26 категорий в девяти семействах) по тридцати уровням.
Слова тем — собственный белый список: частотность в субтитрах для них не показатель
(крыжовник и стамеска там почти не встречаются, а знают их все), поэтому словарь
принимает их наравне с ядром.

Генератор кладёт в блок два-три слова из темы: якорь, соблазн и, с пятого уровня,
слово средней длины. Слова вплетаются друг в друга — путь ищется по всей фигуре
и проходит через уже занятые клетки, если буква совпадает. Если тема не подошла,
генератор молча берёт слово из общего словаря. Тематические слова в пределах уровня
не повторяются, иначе одна и та же приманка стоит в трёх блоках подряд.

Узнаваемость слов идёт по кривой в три ступени (`poolDepth` в difficulty.ts).
До третьего уровня прячется только ядро категории (`core` в themes.json, 200 слов):
ВОЛК, ЛИСА, ЗАЯЦ — то, что называют первым, не задумываясь. До тринадцатого —
вся ходовая часть (`common`, 423 слова из 1107). Дальше вся категория целиком.
АЙВА и РЯПУШКА такие же фрукты и рыбы, как ЯБЛОКО и ЩУКА, но игрок, который
не знает слова, не ищет его, а гадает.

Ядро размечено руками, и это не лень: частотность в субтитрах для узнаваемости
не работает в обе стороны. ЗАЯЦ, БЕЛКА, ЛЕВ и МЫШЬ в частотный словарь не попали
вовсе, хотя их знает каждый ребёнок, а ЛОСЬ, БЫК и БАРСУК попали — и именно они
вылезали в первый уровень. Поэтому список очевидного — свой, по категории на десяток слов.

Засчитываются при этом любые слова темы: если редкое слово сложилось случайно,
оно всё равно из категории.

Блоки уровня берут категории по очереди, по одной на блок. Иначе три блока подряд выходили про одно и то же —
уровень из пяти «Зверей» читается как один длинный блок. Якорь берётся из своей
категории всегда; соблазн — из пары «своя плюс та, что через одну» (`duoPool`
в генераторе). Пара нужна потому, что одна ходовая категория иначе расселяется
по всем пяти блокам: слова вроде ЛЕВ и КОТ складываются где угодно, и подпись
повторяется у соседей — игрок видит «Звери» и в первом блоке, и во втором, хотя
в плане у них разные категории. Шаг через одну при пяти категориях как раз
разводит соседей: {1,3}, {2,4}, {3,5}, {4,1}, {5,2} — соседние пары не пересекаются.

Это предпочтение, а не запрет. Если слова нужной длины в паре нет, соблазн берётся
из всей темы, но уже без категорий соседних блоков — предыдущего и следующего.
Проверка блока (`accepts`) при этом всегда знает тему целиком: засчитывается она
вся, и слово длиннее якоря из «чужой» категории сделало бы блок непроходимым.
Уступки идут по очереди и в понятном порядке: сначала слабеют рамки фигуры,
потом расширяется запас соблазнов и только в самом конце отпускается категория
якоря — она держит подпись, поэтому отдаётся последней.

Одно и то же слово в уровне засчитывается один раз. `usedAnchors` запрещает
класть слово повторно, но солвер находит в блоке и то, чего никто не клал: КОТ,
КЕД и ЛЕВ складываются почти из любой россыпи букв. Поэтому блок со словом темы,
уже найденным в этом уровне, отвергается прямо в `generateFigure`: он
откладывается в запас, а генератор идёт пробовать другую форму и другой якорь.
Часто дело именно в якоре — у ТУФЛИ короткое слово темы осталось одно, и это
ровно то, что уже нашли. Ищем недолго: `SPARE_PATIENCE` форм после первого
запасного варианта, иначе на скудных категориях генератор перебирал бы блок
секундами. Чистого может не существовать вовсе — тогда берём запасной, повтор
неприятен, но пустое место вместо блока хуже. Было 6 повторов слов темы на 150
блоков в русском и 1 в английском, стало 0 и 0 из 174.

Слово из категории соседнего блока в блоке тоже не нужно — и лечится оно тем же
способом, что повтор. Мало запретить его подкладывать: в категории может не
оказаться слова нужной длины, тогда соблазн берётся из общего словаря, а там
чаще всего попадаются ДОМ, РОТ и КОТ — они же слова тем. Поэтому список слов
соседних категорий (`shun`) вычитается и из общего словаря, и из проверки блока:
блок с таким словом откладывается в запас, а генератор пробует другую форму
и другой якорь. Без этого на трёхкатегорийных уровнях соседи совпадали почти
всегда: категорий мало, а короткие слова у всех общие.

Поверх этого генератор пересобирает блок, пока подпись повторяет соседа или
третью встречу той же категории в уровне, и оставляет самый непохожий из пяти
вариантов. Чистого может не найтись вовсе — трёхбуквенные слова складываются
из случайных букв сами, — поэтому берётся лучший, а не идеальный. Мера простая:
категория из подписи соседнего блока. Было 77 таких блоков из 150 в русском
и 68 из 150 в английском, стало 1 и 1 из 174. Генерация уровня — медиана около 18 мс,
худший случай (второй уровень: слов в ядре категорий совсем мало) — около 0,5 с.

Блоков в уровне столько, сколько велит кривая, а не всегда пять: три на первых
двух уровнях, четыре на третьем и четвёртом, пять до десятого, шесть до
двадцатого и семь дальше (`curve.blocks` в пакете языка, `levelBlocks`
в `difficulty.ts`). Короткое знакомство в начале и длинная партия к концу —
это такая же ось сложности, как длина слова и размер блока. Категорий в теме
ровно столько же, сколько блоков, поэтому расписание продублировано
в сборщике планов (`tools/plan.py`, `BLOCKS`): меняешь кривую — пересобирай
планы для обоих языков. Семейств всего шесть, поэтому при шести-семи блоках
повтор семейства в наборе неизбежен, и сборщик ослабляет это требование
ступенями. В очереди под полем показываем не больше четырёх ближайших блоков:
семь ужимаются до нечитаемых крошек.

На первом уровне, пока игрок не повёл пальцем, на месте собираемого слова стоит
подсказка «Найдите длинное слово» (`tutorHint` в пакетах). Она гаснет с первой же
буквой и возвращается с каждым новым блоком. Вынута из потока, иначе полоса букв
дёргалась бы по высоте, когда подсказка исчезает. Текст короткий намеренно: он
стоит в одну строку, а полная фраза «в любой категории» на телефоне в строку
не влезает ни при каком читаемом кегле — и категории всё равно написаны
над блоком.

В ядре категорий нет слов, которые по-русски пишутся через Ё: КЛЁН, ОРЁЛ, БЕРЁЗА,
САМОЛЁТ, АКТЁР. В игре они выглядят как КЛЕН и ОРЕЛ, и на первых уровнях это
читается как ошибка. В `common` и во всей категории они остались — там игрок уже
привык к условности.

Пара категорий для приманок работает, только когда категорий в уровне четыре
и больше. На коротких уровнях их три, и шаг «через одну» упирается в категорию
соседнего блока: первый блок разбирал слова третьего, а третьему потом не из
чего было выбирать — он собирался с восьмидесяти попыток вместо одной.

С третьего уровня якорь обязан хотя бы раз свернуть, а дальше по кривой —
дважды (`minTurns` в параметрах фигуры). Прямое слово игрок читает по строке,
не ища его: на первых двух уровнях это и нужно, дальше — уже скучно. Проверка:
прямых якорей с третьего уровня должно быть ноль.

С пятого уровня (`curve.tangleFrom`) сложность растёт запутанностью, а не
словарём. Слова остаются теми же самыми, трудно становится не читать их,
а находить. Три рычага:

Якорь сворачивает не меньше двух раз, дальше по кривой — трёх.

Подложенные слова обязаны пересечь уже уложенные (`crossing`): два слова
в одних клетках путают взгляд сильнее, чем два слова рядом. Если пересечь
не получается, слово кладётся как выйдет — блок без соблазна хуже блока
без пересечения.

В блоке появляются ложные начала (`falseStarts`): клетки с первой буквой якоря,
от которых слово не собирается, — одна с пятого уровня, две с десятого.
У одного из них ставится и вторая буква: тупик на втором шаге обманывает
лучше, чем на первом. Клетки под них берутся не все — починке нужно оставить
свободные, иначе блок перестанет собираться вовсе.

Аудит печатает сводку запутанности по ступеням: поворотов на блок, клеток
с первой буквой якоря, доля блоков со скрещенными словами. На пятом уровне
эти числа обязаны заметно подскочить — сейчас 1,3 → 2,6 поворота, 1,1 → 1,9
начала и 64 % → 100 % скрещенных.

Множественное число слов темы засчитывается наравне с единственным: игрок читает
с блока то, что видит, и собранные ТУФЛИ обязаны считаться так же, как ТУФЛЯ.
Формы лежат в `themes.json` в карте `plural` и в словаре языка (без них солвер
слово просто не найдёт); собирает их `tools/plural.py` — для русского через
pymorphy, для английского правилами со списком исключений. Скрипт идемпотентный:
перед добавлением он убирает формы прошлого прогона. Прятать генератор
продолжает единственное число — за это отвечает `categoryPool`, а за подсчёт
`themeScoring`. Ё в формах свёрнута в Е: вся игра живёт без Ё, и словарь обязан
хранить ровно то, что читается на блоке.

На первых двух уровнях слова лежат только слева направо и сверху вниз
(`curve.readableUntil`, флаг `readable` в параметрах фигуры). Зеркальная ЛИСА
читается как АСИЛ, и пока игрок не понял правила, это не сложность, а путаница.
Ограничение действует и на якорь, и на подложенные слова: игрок ведёт пальцем
и по ним. С третьего уровня направление свободное.

К шести исходным семействам добавлены «Еда» (еда, сладости, напитки), «Человек»
(тело, семья) и «Школа». Категорий стало 26 вместо 20, и почти все новые — первого
яруса прозрачности: они кормят как раз ранние уровни, где выбор был самым узким.
Каждое слово темы обязано быть в словаре языка, иначе блок с ним непроходим;
проверять это стоит сразу после правки списков.

Раскладка тем по уровням не случайна, и проверять её нужно тремя условиями сразу.
У пары должно быть столько слов каждой нужной длины, сколько блоков её просят,
и с запасом: слова темы внутри уровня не повторяются. Обе категории обязаны
звучать, иначе подпись врёт — «Посуда · Музыка» с одной только музыкой в блоках.
И у пары обязаны быть слова под соблазн: соблазн короче якоря на три буквы,
то есть для якоря в четыре буквы это ровно три, и без трёхбуквенных слов блок
не собирается вовсе (на этом развалилась пара «Мебель · Транспорт»).
Проверка одна: `npm run gen -- themes 30` должен показать 150 якорей из 150.

Прозрачность категории — такой же параметр кривой, как длина слова и размер блока,
и она не совпадает с частотностью слов. Дело не в том, знает ли игрок слово, а в том,
подсказывает ли название, что искать. «Посуда» — предметы на кухне, думать нечего.
«Музыка» может быть и инструментом, и жанром, и нотой; «погода» — состояние, а не
предмет; «спорт» — занятие. Поэтому у категорий есть ярус (`clarity` в themes.json):
первый — предметы из детского словаря, второй — знакомое, но требующее шага в сторону
(рыбы, насекомые, ягоды, инструменты), третий — абстрактное (погода, спорт,
музыка, профессии). До четвёртого уровня берётся только первый ярус, до двенадцатого
первый и второй, дальше все. Так первый уровень выходит из ЗВЕРЕЙ, ОВОЩЕЙ, ПТИЦ,
ЗДАНИЙ и ДЕРЕВЬЕВ, а не из РЫБ со СКАТОМ.

В паре категории стоят по прозрачности: первая понятнее. Её словами генератор прячет
первый блок уровня (`openingPool` в generator.ts) — игрок входит в уровень по очевидной
ассоциации, а смешение начинается со второго блока. Если слов нужной длины в одной
категории не хватило, генератор берёт всю тему: непроходимый блок хуже смешанной подписи.

Категорий в уровне столько же, сколько блоков: пять, по одной на блок, и внутри
уровня они не повторяются. Первый уровень — «Звери · Овощи · Птицы · Здания ·
Деревья»: МЫШЬ, ТЫКВА, ОРЁЛ, ЗАВОД, ЛИПА.

Пара и тройка выглядели однобоко: при пяти блоках категории шли по кругу
и возвращались, и уровень читался как один длинный блок. Сложность держат другие
оси — длина слова, размер и форма блока, узнаваемость слов и прозрачность самих
категорий; ширину темы для этого использовать не нужно.

Ограничения набора: категории берутся из разных семейств (одно повторение
допускается — первых ярусов в семействе бывает всего одна-две категории),
с предыдущим уровнем пересекается не больше двух категорий, а категория,
стоявшая два уровня подряд, третий пропускает. Иначе транспорт оказывался
в первых четырёх уровнях кряду. Один и тот же набор за тридцать уровней
не повторяется. Правки живут в скрипте плана (PER_LEVEL), сам план —
данные в themes.json.

На карте уровня категорий больше не видно — пять названий превращали карту
в стену текста. Они остались в подсказке карточки, а в игре игрок и так видит
категорию над каждым блоком.

Категории уровня всегда из разных семейств: «Овощи · Погода» интереснее
«Фруктов · Овощей», потому что подпись блока сразу говорит, в какую сторону думать,
а две родственные категории сливаются в одну. Поэтому у строки плана больше нет
поля `family` — у такой тройки нет одного имени, и на карте уровня написаны все
три категории. Родство осталось в `families` как данные: оно нужно, чтобы план
не ставил в одну тему соседей (сам план считается скриптом вне сборки).

Над блоком подписаны категории спрятанных в нём слов (`Figure.labels`) — это и есть
правило, по которому считаются слова. Одно слово подписывается одной категорией, даже
если состоит в двух (сирень есть и в деревьях, и в цветах). Якорь обязан быть из темы:
блок с чужим якорем был бы непроходим, поэтому если слов нужной длины в категориях нет,
генератор берёт ближайшую длину, а не чужое слово.

Якорь доходит до одиннадцати букв: в общем словаре слова длиннее девяти не живут,
но категории тем — свой список, и длинные слова есть только там. Солвер поэтому ищет
до двенадцати букв.

Форма блока идёт по кривой отдельно от размера (`shapeStage`): до четвёртого уровня
только плотные и симметричные силуэты, до девятого добавляются вытянутые, дальше —
скелеты с дырками и коридорами в одну клетку. Сначала блок должен читаться с одного
взгляда, иначе новичок не понимает даже правила свайпа.

Габарит блока растёт вместе с числом клеток и по ширине охотнее, чем по высоте
(`box` в difficulty.ts, веса стилей в shape.ts): под блок на телефоне отведено
больше ширины, чем высоты, поэтому вытянутая вбок фигура выходит крупнее той же
фигуры, вытянутой вверх. К концу кривой блок доходит до 18 клеток в габарите 7×6.

Страница не прокручивается вовсе (`body { overflow: hidden }`): игра живёт в один
экран, а прокручивается только карта уровней внутри себя. Поэтому всё, что может
разрастись, обязано ужиматься — список найденных слов ужимает плитки на узком экране,
на низком экране (`max-height: 720px`) ужимается вся обвязка, а поле блока рассчитывает
клетку по фактическому остатку. Ломается это незаметно: на десктопе в коротком окне
сразу появляются полосы прокрутки.

Монеты — единственная экономика игры: 20 за пройденный уровень, 30 за безупречный
(в каждом блоке взято самое длинное слово и без подсказок), 5 за повтор уже пройденного,
чтобы лёгкий уровень не превращался в ферму. Плюс сундук: каждый новый пройденный
уровень двигает полоску, на десятом сундук открывается и высыпает 100 монет — это повод
сыграть ещё один уровень прямо сейчас. Вся экономика живёт в `applyResult` одним местом.
Тратятся монеты только на подсказку — 25 штук за клетку. Каждое нажатие
открывает следующую клетку загаданного слова: одна показывает, где слово
начинается, две — ещё и куда оно идёт. Раньше подсказка светила всегда одну
и ту же клетку, и второе нажатие выглядело сломанной кнопкой. Когда слово
открыто целиком, кнопка молчит и денег не берёт.
Бесплатная подсказка обесценивает поиск, поэтому цена и кошелёк видны всегда:
цена на самой кнопке, кошелёк в шапке.

Копилка «доп. слов» (`SaveData.bonus`, звезда в нижней полосе) — вторая награда игры,
единственная не связанная с целью уровня. Слово языка не из темы блок не рассыпает
и букв не даёт, но показывается золотым с подписью «в копилку», мигает звездой
и ложится в список. Каждые двадцать разных слов приносят 20 монет. Повтор не платит:
копилка хранит именно список слов, а не число, иначе выгодно было бы переигрывать
один и тот же блок. Материал для неё есть: чужие слова встречаются в 90 % блоков,
в среднем по три на блок.

Находка долетает до копилки буквами: слово срывается со своих клеток и уходит
в звезду (`BonusFlight`), звезда мигает в момент прилёта, а не в момент свайпа.
Повтор уже собранного слова честно пишет «уже было» и ничего не начисляет —
иначе непонятно, почему счётчик не двигается.

Зачем это нужно: жёлтый отказ раньше читался как «слово потеряно, ты ошибся»,
хотя игрок нашёл настоящее слово языка. Теперь та же находка читается как «зачтено,
но не туда» — правило темы не размывается, а наблюдательность вознаграждается.
Копилка общая на всю игру (слова копятся в сохранении и не платят дважды),
но в окне показывается только текущий уровень, а общий счёт идёт строкой под
заголовком. Так принято в жанре, и так честнее по смыслу: список за сотню слов
ничего не сообщает, а «что я нашёл здесь» читается сразу. На звезде по той же
причине счёт уровня — это число меняется на глазах, а общее почти не двигается.

За блоком стоит фон, и он меняется каждые десять уровней (`src/ui/scenes.ts`) —
это классика жанра и единственная награда, которую видно сразу и целиком: сундук
сыплет монеты, а мир за блоком в тот же момент становится другим. Шаг смены
намеренно совпадает с шагом сундука (`CHEST_GOAL`), ломать это врозь нельзя.

Пока фон — ровная сине-зелёная заливка, у каждой главы свой оттенок. До этого
там были нарисованные вектором пейзажи; они честно показывали, что они вектор,
и спорили с плитками за внимание, поэтому убраны (история лежит в гите).
Точка замены ровно одна: `SCENES` отдаёт готовый `background-image`, так что
вместо градиента туда ляжет `data:image/webp;base64,…`, когда появятся настоящие
картинки, и остальной код об этом не узнает. Пять картинок под телефон весят
около мегабайта — примерно вдвое больше нынешней сборки, это и есть цена вопроса.

Палитра спокойная сине-зелёная: фон тёмный и ровный, панели (шкала цели,
найденные слова, вступление на карте) врезаны в него плашками того же семейства,
но темнее. Яркого на экране ровно три вещи, и все три — то, с чем игрок
взаимодействует: кремовый блок, зелёная кнопка и золотая подсказка.
Свободный текст поверх фона идёт с тенью, подписи на цветных кнопках белые
с тёмной тенью — цветной текст на цветной заливке на телефоне не читается.
Закрытые уровни на карте не бледнеют, а глохнут в тёмный: полупрозрачная
карточка выглядела бы сломанной, а не запертой.

Блок обведён по контуру тёмным (`.plate .rim` — тот же путь фигуры, только шире;
та же обводка у миниатюр очереди, и там она рисуется двумя путями по той же
причине): светлые клетки без канта тонут в фоне, а тень
одна этого не решает, потому что работает только на светлом. Кант тонкий и с тенью
того же цвета вниз на высоту нижней грани — обводить надо весь объём, а не плоскую
верхнюю грань, иначе тёмная полоса ложится поверх грани и нижний ряд клеток
выглядит обрезанным.

Подпись категории обведена тем же тёмным цветом, обводка собрана из восьми теней
по кругу: `-webkit-text-stroke` режет букву изнутри и делает шрифт тоньше. Тень
под подписью идёт отдельным фильтром, а не девятой тенью в списке, — фильтр
отбрасывает её от всей буквы вместе с кантом, а не от одной заливки под ним.

Кнопки, монеты и звёзды сделаны в идиоме казуальных игр: заливка градиентом,
тёмная нижняя грань вместо тени, проседание при нажатии, блик на звезде и монете.
Это не украшательство: на телефоне такая кнопка читается как физическая и явно
приглашает её нажать, а плоская — нет. Палитра кнопок задана переменными
(`--go`, `--gold` и их грани) — трогать их поштучно в местах использования нельзя,
иначе экраны разъедутся.

Переход к следующему уровню сделан двумя мелочами, которые вместе решают всё.
Полоска прогресса на новой партии не отматывается назад, а появляется пустой:
у неё ключ по номеру запуска (`run` в App.tsx), поэтому React пересоздаёт её,
а не анимирует ширину от старого значения к нулю. Окно итогов уходит с затуханием
(`.overlay.out`, 220 мс) и только потом меняется уровень — иначе следующий блок
выезжал из-под ещё видимой карточки.

Экран победы устроен как в жанре принято: три звезды (всегда три — это праздник,
а не оценка), крупное «Браво!», строка похвалы, награда монетами и широкая кнопка
следующего уровня. Ничего больше: разбор партии со счётом и упущенными словами
на празднике лишний. Экран поражения — наоборот: без звёзд и награды, зато со счётом
и объяснением, чего не хватило.

Собираемое слово висит по центру свободного места — между шкалой цели сверху
и подписью категорий снизу, поровну от обеих. Прижатое к какому-нибудь краю
оно читается как часть шкалы или как часть подписи. Отступа сверху у сцены
намеренно нет: он оказывался вне строки со словом и сдвигал его на 12 пикселей
вниз, ломая равенство зазоров.

Блок по ширине стоит по центру, а по высоте прижат к низу — и это осознанно:
до низа дотягивается палец, и блок не прыгает по вертикали от блока к блоку,
какой бы он ни был высоты. Пустое место собирается над ним, а не под ним, и там
же появляется собираемое слово. Центрировать блок в остатке я пробовал: короткий
блок повисал в воздухе, и низ экрана пустовал.

Управление собрано в нижнюю полосу (`.tray`): слева группа кнопок (`.tray-left`) —
копилка у самого края и подсказка по центру промежутка между нею и счётчиком блоков
(группа растянута на всю колонку, подсказка центруется автополями). Высота обеих
кнопок задана одной переменной `--tray-btn`: разной высоты они стояли вразнобой,
а полоса должна читаться одной линией. По центру полосы
счётчик блоков, правее миниатюры очереди и до края экрана. Очередь мерит ширину всей
левой группы, а не одной подсказки, и ужимает только сами миниатюры: зазоры между ними
заданы в пикселях и множителем не трогаются, иначе очередь вылезает за край ровно
на несъеденные зазоры. Блок из-за этого стоит по центру всей ширины,
а не в остатке рядом с колонкой очереди, и на телефоне получается заметно крупнее.
Миниатюры очереди стоят по центру полосы, а не на общей нижней линии: они разной
высоты, и на узком экране ужатая очередь прижималась к самому низу экрана.
Кнопка отладки уехала в шапку — в полосе для неё места нет. В самой панели
осталось два дела: посмотреть слова блока (тематические зелёным, прочие жёлтым)
и сбросить прогресс. Сид, счётчики, авто-проход и смена сида были нужны, пока
настраивался генератор, и убраны — на глаз они только мешали. Сброс спрашивает
подтверждение вторым нажатием и через три секунды забывает вопрос.

На экране поражения стоит та же шкала цели, что в шапке: «не хватило» звучит
абстрактно, а полоска сразу показывает, насколько именно.

В окне итогов кнопки «к карте» нет ни в победе, ни в поражении: в ряду стоит одно
действие — «следующий уровень» или «ещё раз», — а уйти на карту можно домиком
в шапке. Разбор поражения («собрано столько-то из стольких») набран крупнее
остального текста карточки: это единственное, что на том экране читают.

Осторожно с селекторами в дымовом тесте: класс `big` есть и у кнопки в ряду,
и у средней звезды в заголовке окна. Тест жмёт `.card .row button`.

Дымовой тест из-за этого проходит уровень настоящими свайпами: якорь он берёт
как самое длинное тематическое слово из панели отладки. Так надёжнее — тест
проверяет то же, что делает игрок, а не служебную кнопку.

Игра открывается сразу на последнем доступном уровне (`latestLevel` в `App.tsx`),
а не на карте: игрок почти всегда возвращается доигрывать, и лишний экран между
ним и блоком — лишнее касание. Сброшенный прогресс — это `unlocked = 1`, отдельного
случая для него нет. Карта осталась за кнопкой «назад» в шапке и за кнопкой на
экране итогов.

Между блоком и полосой держим ощутимый зазор: у подложки есть кант наружу и
«толщина» вниз, поэтому видимый низ детали ниже последней плитки примерно на
два десятка пикселей. Это учтено дважды — в нижнем отступе сцены
(`padding-bottom` у `.stage`) и в запасе `BOTTOM_AIR` в `Board.tsx`, из которого
считается размер клетки. Считать по одним плиткам нельзя: высокий блок на
невысоком экране краем заезжал под кнопки.

Кнопка «во весь экран» вместе с полным экраном закрепляет книжную ориентацию
(`screen.orientation.lock('portrait')`): часть мобильных браузеров во весь экран
уходит в альбом вслед за датчиком поворота, а игра рассчитана на вертикальный
экран. Замок снимается и при выходе через нашу кнопку, и при выходе системным
«назад» — по событию `fullscreenchange`. Отказ браузера игре не мешает.

Тёмная подложка под текстом (`text-shadow` у `button`) снята с золотых элементов
с тёмными буквами — счётчик копилки: там жёсткая тень в два пикселя читается
как двоящийся текст.

Шкала цели сделана жёлобом, а не плашкой: глубокая тёмная выемка, светлая
нижняя грань и налитая полоса с бликом по верху. Плоской она сливалась со
списком найденных слов, который лежит прямо под ней, и читалась как ещё одно
поле, а не как главный счётчик уровня.

Кнопки шапки — из того же материала, что кнопки нижней полосы: синие, с тёмной
гранью и проседанием. Полупрозрачные «призраки» читались как неактивные, хотя
назад и полный экран нажимают чаще всего остального. Все три — квадратные значки
42×42: домик на карту, стрелки в углы на полный экран и жук на отладку. Со
словами они не умещались на узком телефоне, а эти три значка понятны без подписи;
сами подписи остались в `title` и `aria-label` и живут в языковых пакетах
(`fullscreen`, `fullscreenExit`, `fullscreenTitle`). Значки стоят слева в ряд,
по центру промежутка между ними и кошельком подписан уровень (`levelName`),
а на узком экране подпись сокращается до «Ур. 3» (`levelNameShort`): обрезать её
многоточием хуже, чем сократить.

Подсказка и копилка одного синего цвета: это пара кнопок одной полосы, а золотом
в игре помечены деньги, а не действия. Внутри подсказки две строки — сверху
лампочка и цена, снизу само слово: цену видно первой, а слово работает подписью
к значку.

История решений лежит в `notes/`: исходный план, разбор баланса первых десяти уровней,
устройство раздачи и журнал этапов. Это архив «почему», а не инструкция: если записи
расходятся с этим файлом, прав этот файл.

`src/game` — правила партии и сохранение прогресса. `src/ui` — интерфейс на React.
`tools` — сборка одного html, консольный прогон, дымовой тест, пересборка словаря.

Игра собирается в единственный самодостаточный файл: код, словарь и стили внутри,
внешних запросов нет. `wordblocks.html` открывается с диска, `docs/index.html` — та же
сборка для GitHub Pages. Оба файла машинные, правь исходники и пересобирай.

## Проверка перед живым игроком

`npm run audit` прогоняет все тридцать уровней обоих языков и ищет вырожденные
случаи — то, что ломает партию не ошибкой, а скукой или несправедливостью:
блок без выбора (кроме якоря нет слова темы короче), слово темы длиннее якоря,
якорь не из своей категории, слово и его же множественное число в одном блоке,
повтор слова темы между блоками, подпись, повторяющая соседа, прямой якорь
после второго уровня, зеркальный якорь на первых двух, палка вместо фигуры,
каша из слов, цель, которая берётся самыми короткими словами, и блок,
не влезающий в телефон. Отдельно печатаются «шероховатости» — то, что глаз
заметит, а партию не испортит: например, один и тот же якорь на соседних
уровнях (ВИШНЯ живёт и во фруктах, и в деревьях).

Перед тем как давать игру живому игроку, аудит должен показывать ноль
вырожденных случаев на обоих языках. Если план тем пересобирается, его сид
(`PLAN_SEED` в `tools/plan.py`) подбирается под аудит: планов много, и они
заметно разной ровности — текущий сид проверен.

## Рабочие правила

Комментарии и тексты интерфейса на русском. Комментарий объясняет зачем, а не что.

После правок в ядре — `npm test`, после правок в интерфейсе — `npm run build` и `npm run smoke`.
Перед коммитом собранные файлы должны быть пересобраны, иначе опубликованная версия разойдётся
с исходниками.

Публикация для команды: `npm run build`, затем коммит и пуш в main. GitHub Pages раздаёт
из папки `/docs` по адресу https://dzmitryanushkevich-cloud.github.io/wordblocks/

Кто делает пуш, зависит от того, где идёт работа, и это не мелочь. Из облачной
сессии Cowork команды на этой машине не выполняются вовсе — оттуда правки только
записываются в папку, а пуш остаётся за человеком (`git-push.bat`). Когда работа
идёт из Claude Code прямо в этой папке, оболочка есть, токен GitHub берётся из
диспетчера учётных данных Windows, и тогда порядок такой: `npm test`,
`npm run build`, `npm run smoke`, коммит, пуш. Собранные файлы обязаны быть
пересобраны до коммита, иначе опубликованная версия разойдётся с исходниками.

## Что в работе

Кривая первых десяти уровней переписана вручную (`OPENING` в `src/core/difficulty.ts`),
но живых впечатлений от игры пока нет — это следующая проверка.

Темы расписаны на тридцать уровней, дальше идут по кругу. Когда уровней станет
больше тридцати, список категорий надо расширять, а не растягивать круг.

Плотность блоков поднята вслед за подписью: около 5,5 слова на блок вместо 3,4.
Живой игрой это ещё не проверено — если окажется, что густые блоки утомляют,
первым делом вниз идут `words` и `short` в OPENING.

Цель уровня — 78 % от суммы якорных слов, но не ниже, чем «худшая игра плюс
буква»: если в каждом блоке взять самое короткое слово темы, уровень обязан
провалиться. Без этого пола второй и третий уровни выигрывались любой игрой.

Долг по мусору: из папки нужно удалить `src/data`, `src/core/loadDictionary.ts`
и `src/ui/plural.ts` — они остались от старых решений, в сборке не участвуют
и только путают. Из облачной сессии удалить их нечем: там есть запись файлов,
но не удаление. У кого есть оболочка — удалите и закоммитьте.

Фон сейчас ровная заливка, настоящих пейзажей нет. Если появятся растровые
картинки, менять одно место: `SCENES` в `src/ui/scenes.ts` отдаёт готовый
`background-image`, туда вместо градиента ложится `data:image/webp;base64,…`.
