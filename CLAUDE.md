# WordBlocks

Прототип словесной головоломки на русском. Игрок свайпом по соседним плиткам фигуры
собирает слово; как только слово найдено, оно засчитывается мгновенно, а вся фигура
рассыпается вместе с остальными спрятанными в ней словами. Пять фигур на уровень,
прогресс считается в буквах — поэтому короткое слово это потерянные буквы.

Считаются только слова из категорий уровня — они написаны над блоком (`Figure.scoring`).
Остальные слова языка в блоке неизбежны (ЛАЙ внутри ЛАЙМА, ЛИС внутри ЛИСЫ: чистых блоков
выходило 10 из 150) и потому безвредны: на них игра отвечает жёлтым отказом, блок стоит.
Это правило держит всю честность игры, не трогай его не подумав.

Главный конфликт игры: генератор специально кладёт в каждый блок длинное якорное слово
и короткое слово-соблазн — оба из темы. Без соблазна выбирать не из чего, а без длинного
якоря нечего искать.

## Команды

    npm install                  только для разработки
    npm run build                пересобирает wordblocks.html и docs/index.html
    npm run build -- --artifact  плюс dist/artifact.html для публикации в Claude
    npm run gen                  консольный прогон генератора: уровни 1, 5 и 10
    npm run gen -- en stats 40   то же для другого языка: первым аргументом код языка
    python tools/build-dictionary-en.py   пересборка английского словаря (нужен WordNet)
    npm run gen -- stats 200     статистика генератора по 200 уровням
    npm run gen -- themes 30     какие якоря попали в тему уровня
    npm test                     тесты ядра (vitest)
    npm run smoke                дымовой тест интерфейса в браузере (нужен playwright-core)
    npm run typecheck            проверка типов

## Устройство

Игра многоязычная по строению: всё, что зависит от языка, лежит в `src/content`
и передаётся в ядро параметром — словарь, категории с планом по уровням, кривая
сложности и тексты интерфейса. Ядро (рост фигур, пути, солвер, генератор, правила
партии) не знает ни одного языка. Сейчас в сборке два пакета: `ru` и `en`.
Новый язык — это новая папка в `src/content` и строчка в реестре
`src/content/index.ts`; ядро при этом не трогается вовсе. Если тянет положить
русскую строку в `src/core` или `src/ui` — это ошибка, строка идёт в пакет.

Язык выбирается при запуске: `?lang=ru` в адресе, потом выбор игрока из переключателя
на карте уровней, потом язык браузера, потом язык по умолчанию (русский). Прогресс
хранится отдельно на каждый язык. Дымовой тест читает русские подписи и поэтому
открывает игру с `?lang=ru` — иначе в браузере с английской локалью он падает.

Кривая у каждого языка своя, и это не формальность: английские слова короче
и коротких слов в языке в разы больше. Поэтому у `en` якорь доходит до десяти букв
вместо одиннадцати, а ограничения на число слов в блоке вдвое свободнее — иначе
валидатор бесконечно чинит блок из-за случайных CAT, EAR и PEA. Считаются всё равно
только слова темы, так что шум безвреден.

`src/core` — чистый TypeScript без React: словарь с префиксным деревом, рост полиомино,
солвер всех слов фигуры, генератор с валидатором, кривая сложности. Ядро гоняется из консоли
и из тестов, в нём не должно появляться ничего браузерного.

У каждого уровня есть тема: `src/core/themes.ts` раскладывает категории из
`src/content/<язык>/themes.json` (в русском 20 категорий, около тысячи слов) по тридцати уровням.
Слова тем — собственный белый список: частотность в субтитрах для них не показатель
(крыжовник и стамеска там почти не встречаются, а знают их все), поэтому словарь
принимает их наравне с ядром.

Генератор кладёт в блок два-три слова из темы: якорь, соблазн и, с пятого уровня,
слово средней длины. Слова вплетаются друг в друга — путь ищется по всей фигуре
и проходит через уже занятые клетки, если буква совпадает. Если тема не подошла,
генератор молча берёт слово из общего словаря. Тематические слова в пределах уровня
не повторяются, иначе одна и та же приманка стоит в трёх блоках подряд.

У каждой категории есть ходовая часть (`common` в themes.json, 423 слова из 1107):
до тринадцатого уровня прячутся только её слова. АЙВА и РЯПУШКА такие же фрукты
и рыбы, как ЯБЛОКО и ЩУКА, но игрок, который не знает слова, не ищет его, а гадает.
Засчитываются при этом любые слова темы: если редкое слово сложилось случайно,
оно всё равно из категории.

Раскладка тем по уровням не случайна, и проверять её нужно тремя условиями сразу.
У пары должно быть столько слов каждой нужной длины, сколько блоков её просят,
и с запасом: слова темы внутри уровня не повторяются. Обе категории обязаны
звучать, иначе подпись врёт — «Посуда · Музыка» с одной только музыкой в блоках.
И у пары обязаны быть слова под соблазн: соблазн короче якоря на три буквы,
то есть для якоря в четыре буквы это ровно три, и без трёхбуквенных слов блок
не собирается вовсе (на этом развалилась пара «Мебель · Транспорт»).
Проверка одна: `npm run gen -- themes 30` должен показать 150 якорей из 150.

Смешивание идёт по кривой, как и всё остальное. Первые два уровня — одна
очевидная категория («Рыбы», «Звери»): игрок сначала должен понять само правило,
а не гадать, при чём тут посуда рядом с музыкой. Третий и четвёртый — родственная
пара («Фрукты · Овощи»), и только с пятого идут пары из разных семейств.
Правки этой кривой живут в скрипте плана (SOLO_UNTIL и KIN_UNTIL), сам план —
данные в themes.json.

Пара дальше пятого уровня всегда из разных семейств: «Овощи · Погода» интереснее «Фруктов · Овощей»,
потому что подпись блока сразу говорит, в какую сторону думать, а две родственные
категории сливаются в одну. Поэтому у строки плана больше нет поля `family` —
у такой пары нет одного имени, и на карте уровня написаны обе категории.
Родство категорий осталось в `families` как данные: оно нужно, чтобы план
не ставил в пару соседей (сам план считается скриптом вне сборки).

Над блоком подписаны категории спрятанных в нём слов (`Figure.labels`) — это и есть
правило, по которому считаются слова. Одно слово подписывается одной категорией, даже
если состоит в двух (сирень есть и в деревьях, и в цветах). Якорь обязан быть из темы:
блок с чужим якорем был бы непроходим, поэтому если слов нужной длины в категориях нет,
генератор берёт ближайшую длину, а не чужое слово.

Якорь доходит до одиннадцати букв: в общем словаре слова длиннее девяти не живут,
но категории тем — свой список, и длинные слова есть только там. Солвер поэтому ищет
до двенадцати букв.

Форма блока идёт по кривой отдельно от размера (`shapeStage`): до четвёртого уровня
только плотные и симметричные силуэты, до девятого добавляются вытянутые, дальше —
скелеты с дырками и коридорами в одну клетку. Сначала блок должен читаться с одного
взгляда, иначе новичок не понимает даже правила свайпа.

Габарит блока растёт вместе с числом клеток и по ширине охотнее, чем по высоте
(`box` в difficulty.ts, веса стилей в shape.ts): под блок на телефоне отведено
больше ширины, чем высоты, поэтому вытянутая вбок фигура выходит крупнее той же
фигуры, вытянутой вверх. К концу кривой блок доходит до 18 клеток в габарите 7×6.

Страница не прокручивается вовсе (`body { overflow: hidden }`): игра живёт в один
экран, а прокручивается только карта уровней внутри себя. Поэтому всё, что может
разрастись, обязано ужиматься — список найденных слов ужимает плитки на узком экране,
на низком экране (`max-height: 720px`) ужимается вся обвязка, а поле блока рассчитывает
клетку по фактическому остатку. Ломается это незаметно: на десктопе в коротком окне
сразу появляются полосы прокрутки.

Монеты — единственная экономика игры: 20 за пройденный уровень, 30 за безупречный
(в каждом блоке взято самое длинное слово и без подсказок), 5 за повтор уже пройденного,
чтобы лёгкий уровень не превращался в ферму. Плюс сундук: каждый новый пройденный
уровень двигает полоску, на десятом сундук открывается и высыпает 100 монет — это повод
сыграть ещё один уровень прямо сейчас. Вся экономика живёт в `applyResult` одним местом.
Тратятся монеты только на подсказку — 25 штук за клетку. Каждое нажатие
открывает следующую клетку загаданного слова: одна показывает, где слово
начинается, две — ещё и куда оно идёт. Раньше подсказка светила всегда одну
и ту же клетку, и второе нажатие выглядело сломанной кнопкой. Когда слово
открыто целиком, кнопка молчит и денег не берёт.
Бесплатная подсказка обесценивает поиск, поэтому цена и кошелёк видны всегда:
цена на самой кнопке, кошелёк в шапке.

За блоком стоит фон, и он меняется каждые десять уровней (`src/ui/scenes.ts`) —
это классика жанра и единственная награда, которую видно сразу и целиком: сундук
сыплет монеты, а мир за блоком в тот же момент становится другим. Шаг смены
намеренно совпадает с шагом сундука (`CHEST_GOAL`), ломать это врозь нельзя.

Пока фон — ровная сине-зелёная заливка, у каждой главы свой оттенок. До этого
там были нарисованные вектором пейзажи; они честно показывали, что они вектор,
и спорили с плитками за внимание, поэтому убраны (история лежит в гите).
Точка замены ровно одна: `SCENES` отдаёт готовый `background-image`, так что
вместо градиента туда ляжет `data:image/webp;base64,…`, когда появятся настоящие
картинки, и остальной код об этом не узнает. Пять картинок под телефон весят
около мегабайта — примерно вдвое больше нынешней сборки, это и есть цена вопроса.

Палитра спокойная сине-зелёная: фон тёмный и ровный, панели (шкала цели,
найденные слова, вступление на карте) врезаны в него плашками того же семейства,
но темнее. Яркого на экране ровно три вещи, и все три — то, с чем игрок
взаимодействует: кремовый блок, зелёная кнопка и золотая подсказка.
Свободный текст поверх фона идёт с тенью, подписи на цветных кнопках белые
с тёмной тенью — цветной текст на цветной заливке на телефоне не читается.
Закрытые уровни на карте не бледнеют, а глохнут в тёмный: полупрозрачная
карточка выглядела бы сломанной, а не запертой.

Блок обведён тёмно-синим по контуру (`.plate .rim` — тот же путь, только шире;
та же обводка у миниатюр очереди). Кант тонкий и с тенью того же цвета вниз
на высоту нижней грани: обводить надо весь объём, а не плоскую верхнюю грань,
иначе тёмная полоса ложится поверх грани и нижний ряд клеток выглядит обрезанным, а подпись категории — синей обводкой из восьми
теней. На пёстром пейзаже светлые клетки сливаются то с небом, то с песком,
а белая подпись пропадает совсем; тени одной этого не решают, потому что тень
работает только на светлом фоне.

Палитра дневная и нарочно насыщенная: в этом жанре фон — обещание приятного
времени, а не декорация к напряжению. Расплата за яркость — контраст, поэтому
всё, что несёт текст, стоит на тёмной синей плашке (шкала цели, найденные слова,
вступление на карте, кошелёк), свободный текст поверх неба идёт с тёмной тенью,
а кремовый блок держится плотной тенью — иначе он растворяется в небе.
Закрытые уровни на карте не бледнеют, а глохнут в тёмно-синий: полупрозрачная
карточка на ярком небе выглядела бы сломанной, а не запертой.
Подписи на цветных кнопках белые с тёмной тенью — цветной текст на цветной
заливке на телефоне не читается.

Кнопки, монеты и звёзды сделаны в идиоме казуальных игр: заливка градиентом,
тёмная нижняя грань вместо тени, проседание при нажатии, блик на звезде и монете.
Это не украшательство: на телефоне такая кнопка читается как физическая и явно
приглашает её нажать, а плоская — нет. Палитра кнопок задана переменными
(`--go`, `--gold` и их грани) — трогать их поштучно в местах использования нельзя,
иначе экраны разъедутся.

Экран победы устроен как в жанре принято: три звезды (всегда три — это праздник,
а не оценка), крупное «Браво!», строка похвалы, награда монетами и широкая кнопка
следующего уровня. Ничего больше: разбор партии со счётом и упущенными словами
на празднике лишний. Экран поражения — наоборот: без звёзд и награды, зато со счётом
и объяснением, чего не хватило.

Управление собрано в нижнюю полосу (`.tray`): подсказка слева, счётчик блоков
по центру, миниатюры очереди правее него и до края экрана. Блок из-за этого стоит по центру всей ширины,
а не в остатке рядом с колонкой очереди, и на телефоне получается заметно крупнее.
Кнопка отладки уехала в шапку — в полосе для неё места нет.

История решений лежит в `notes/`: исходный план, разбор баланса первых десяти уровней,
устройство раздачи и журнал этапов. Это архив «почему», а не инструкция: если записи
расходятся с этим файлом, прав этот файл.

`src/game` — правила партии и сохранение прогресса. `src/ui` — интерфейс на React.
`tools` — сборка одного html, консольный прогон, дымовой тест, пересборка словаря.

Игра собирается в единственный самодостаточный файл: код, словарь и стили внутри,
внешних запросов нет. `wordblocks.html` открывается с диска, `docs/index.html` — та же
сборка для GitHub Pages. Оба файла машинные, правь исходники и пересобирай.

## Рабочие правила

Комментарии и тексты интерфейса на русском. Комментарий объясняет зачем, а не что.

После правок в ядре — `npm test`, после правок в интерфейсе — `npm run build` и `npm run smoke`.
Перед коммитом собранные файлы должны быть пересобраны, иначе опубликованная версия разойдётся
с исходниками.

Публикация для команды: `npm run build`, затем коммит и пуш в main. GitHub Pages раздаёт
из папки `/docs` по адресу https://dzmitryanushkevich-cloud.github.io/wordblocks/

Кто делает пуш, зависит от того, где идёт работа, и это не мелочь. Из облачной
сессии Cowork команды на этой машине не выполняются вовсе — оттуда правки только
записываются в папку, а пуш остаётся за человеком (`git-push.bat`). Когда работа
идёт из Claude Code прямо в этой папке, оболочка есть, токен GitHub берётся из
диспетчера учётных данных Windows, и тогда порядок такой: `npm test`,
`npm run build`, `npm run smoke`, коммит, пуш. Собранные файлы обязаны быть
пересобраны до коммита, иначе опубликованная версия разойдётся с исходниками.

## Что в работе

Кривая первых десяти уровней переписана вручную (`OPENING` в `src/core/difficulty.ts`),
но живых впечатлений от игры пока нет — это следующая проверка.

Темы расписаны на тридцать уровней, дальше идут по кругу. Когда уровней станет
больше тридцати, список категорий надо расширять, а не растягивать круг.

Плотность блоков поднята вслед за подписью: 5,4 слова на блок вместо 3,4, в подписи
две категории у 46 блоков из 150. Живой игрой это ещё не проверено — если окажется,
что густые блоки утомляют, первым делом вниз идут `words` и `short` в OPENING.

Цель уровня — 78 % от суммы якорных слов, то есть примерно два коротких слова за пять фигур
можно себе позволить. Проверяется только руками.

Долг по мусору: из папки нужно удалить `src/data`, `src/core/loadDictionary.ts`
и `src/ui/plural.ts` — они остались от старых решений, в сборке не участвуют
и только путают. Из облачной сессии удалить их нечем: там есть запись файлов,
но не удаление. У кого есть оболочка — удалите и закоммитьте.

Фон сейчас ровная заливка, настоящих пейзажей нет. Если появятся растровые
картинки, менять одно место: `SCENES` в `src/ui/scenes.ts` отдаёт готовый
`background-image`, туда вместо градиента ложится `data:image/webp;base64,…`.
