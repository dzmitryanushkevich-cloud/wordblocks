# WordBlocks

Прототип словесной головоломки: связные блоки-фигуры из букв, внутри которых спрятаны слова.
Игрок свайпом по соседним плиткам (вверх/вниз/влево/вправо, без диагоналей, без повторов)
собирает слово. Как только слово найдено — оно засчитывается мгновенно, а вся фигура
рассыпается вместе с остальными спрятанными в ней словами. Фигур в уровне пять,
прогресс считается в буквах: набрал цель за пять фигур — прошёл.

Отсюда весь конфликт: в каждой фигуре генератор специально кладёт длинное якорное слово
и короткое слово-соблазн. Взять быстрое короткое — потерять буквы, которые придётся добирать дальше.

Дизайн-документ лежит в проекте Claude: `claude/wordblocks-plan.md`.

## Как запустить

Открыть `wordblocks.html` двойным кликом. Всё — код, словарь, стили — запечено внутрь файла,
внешних запросов нет, ничего ставить не нужно. Работает и с диска, и с флешки, и офлайн.
Прогресс уровней хранится в localStorage браузера.

## Состояние

Играбельный прототип: карта уровней, игровой экран со свайпом, мгновенный зачёт слова,
рассыпание фигуры, прогресс по буквам, подсказка, экраны победы и проигрыша с разбором
упущенных слов, сохранение прогресса, панель отладки.

## Гит

Репозиторий заводится двойным кликом по `git-init.bat`: он проверит, установлен ли Git
(если нет — подскажет команду `winget install --id Git.Git -e`), при первом запуске спросит
имя и почту для коммитов, создаст репозиторий с веткой `main` и сделает первый коммит.

Из индекса исключены `node_modules`, кеш словаря и скриншоты дымового теста.
Собранный `wordblocks.html` и словарь в репозитории лежат, но помечены как машинные файлы,
чтобы не засорять diff: игра должна работать у любого, кто просто скачал папку.

## Публикация для команды

Игра лежит в репозитории дважды: `wordblocks.html` для запуска с диска и `docs/index.html` —
ровно та же сборка под именем, которое раздаёт GitHub Pages. Оба файла делает `npm run build`.

Порядок один раз:

1. Создать на github.com пустой репозиторий (без README, без .gitignore).
2. Запустить `git-init.bat`, потом `git-push.bat` — он спросит адрес репозитория и отправит код.
3. В настройках репозитория: Settings → Pages → Source «Deploy from a branch», ветка `main`,
   папка `/docs`. Через минуту игра открывается по адресу вида
   `https://имя.github.io/wordblocks/` — без регистрации и входа для тех, кому дашь ссылку.

Дальше любое обновление — это `npm run build` и двойной клик по `git-push.bat`.
Ссылка остаётся прежней, у команды сразу свежая версия.

На бесплатном аккаунте GitHub Pages работает только из публичного репозитория:
код игры увидит любой желающий. Если это не подходит, тот же `docs/index.html` кладётся
на любой другой статический хостинг или на свой сервер — файл самодостаточный.

## Разработка

Файл `wordblocks.html` собирается из исходников; править нужно их, а не готовый html.

```bash
npm install              # только для разработки, игроку не нужно

npm run build            # пересобрать wordblocks.html
npm run gen              # консольный прогон генератора: уровни 1, 5 и 10
npm run gen -- 7         # подробно уровень 7
npm run gen -- stats 200 # статистика по 200 уровням
npm test                 # тесты ядра
npm run smoke            # дымовой тест интерфейса в браузере (нужен playwright-core)
npm run typecheck        # проверка типов
```

## Правила, как они реализованы

Слово ведут свайпом по соседним плиткам (вверх, вниз, влево, вправо; диагоналей нет,
клетка не используется дважды). Возврат пальцем на предыдущую плитку снимает последнюю букву.
Пока слово собирается, оно показано над фигурой и подсвечивается зелёным, как только
становится валидным — так видно заранее, что отпускание его засчитает.

Слово засчитывается мгновенно по отпусканию, если оно есть в словаре и в нём не меньше трёх букв.
Фигура сразу рассыпается вместе со всеми остальными словами, которые в ней были;
в итогах уровня показывается, что именно упущено.

## Как устроен генератор

1. Растим случайный полиомино нужного размера в габарите 4×4 или 5×5, отбрасываем скучные
   формы (прямая полоса, сплошной прямоугольник).
2. Ищем в форме простой путь длины якорного слова и выкладываем по нему узнаваемое слово из словаря.
3. В свободных клетках прокладываем короткое слово-соблазн — без выбора игра теряет смысл.
4. Остальные клетки заполняем буквами по частотности словаря, после чего запускаем цикл починки:
   солвер находит все слова фигуры, и если появилось слово длиннее якоря или лишние
   трёхбуквенные выходы, генератор точечно меняет букву в мешающей клетке (клетки якоря
   и соблазна неприкосновенны) и пробует снова.
5. Уровень — пять таких фигур. Цель по буквам считается как ~78 % от суммы якорных слов,
   но не ниже «три буквы с фигуры плюс одна», чтобы уровень нельзя было пройти одними короткими словами.

Всё детерминировано от сида: один и тот же номер уровня всегда даёт одну и ту же раскладку,
поэтому любую претензию к фигуре можно воспроизвести.

## Словарь

Собран из двух открытых источников: списка существительных
[Harrix/Russian-Nouns](https://github.com/Harrix/Russian-Nouns) и частотного списка
[hermitdave/FrequencyWords](https://github.com/hermitdave/FrequencyWords) по субтитрам 2018 года,
с морфологической проверкой через pymorphy3 (данные OpenCorpora).

Оставлены только существительные единственного числа именительного падежа длиной 3–9 букв,
встречающиеся в корпусе не реже 20 раз, без имён, фамилий, географии и аббревиатур.
Ё приводится к Е. Вульгарное и оскорбительное вырезано списком.

Слова отсортированы по убыванию частоты. Первые 4000 считаются узнаваемыми: только они
прячутся в фигуру как якорь или соблазн. Остальные принимаются как ответ игрока, но сами
в фигуру не закладываются.
